## 📋 Cambios en Base de Datos

```
OPERACIÓN SECUENCIAL:

1. SELECT (tickets) - Leer ticket existente
   ↓
2. SELECT (usuarios) - Buscar usuario invitado
   ├─→ EXISTS → SELECT existente
   └─→ NO EXISTS → INSERT nuevo
   ↓
3. SELECT/UPDATE (datos_fiscales_usuario)
   ├─→ EXISTS → UPDATE con nuevos datos
   └─→ NO EXISTS → INSERT nuevos datos
   ↓
4. SELECT (ticket_detalle) - Leer detalles
   ↓
5. SELECT (ticket_metodo_pago) - Leer métodos de pago
   ↓
6. SELECT (facturas) - Get MAX folio
   ↓
7. INSERT (facturas) - Crear factura nueva
   ↓
8. INSERT (facturas_detalles) - Copiar líneas x N
   ↓
9. UPDATE (tickets) - Marcar como facturado
   ↓
10. UPDATE (facturas) - Set xml_path
    ↓
11. UPDATE (facturas) - Set uuid
    ↓
12. UPDATE (facturas) - Set pdf_path
    ↓
13. COMMIT (o ROLLBACK si hay error)
```

## 🎯 Transacciones y Puntos de No Retorno

```
PUNTO DE NO RETORNO:

┌─ Validaciones (Sin cambios en BD)
│
├─ Lectura de Ticket (Sin cambios)
│
├─ Verificación de Usuario (Sin cambios)
│
├─ INSERT Usuario [CAMBIO 1]
│
├─ INSERT/UPDATE Datos Fiscales [CAMBIO 2]
│
├─ INSERT Factura [CAMBIO 3] ◄─── PUNTO CRÍTICO
│      Una vez insertada, ya existe registro
│
├─ INSERT Detalles [CAMBIO 4]
│
├─ UPDATE Ticket [CAMBIO 5]
│      Marca como "facturado"
│
├─ UPDATE xml_path [CAMBIO 6]
│
├─ UPDATE uuid [CAMBIO 7]
│
└─ UPDATE pdf_path [CAMBIO 8]


CONSIDERACIÓN:
• El sistema NO usa transacciones explícitas (BEGIN/COMMIT)
• Se recomienda agregar si hay procesamiento concurrente
• Cada INSERT/UPDATE es inmediato

RIESGO:
Si falla después de "INSERT facturas" pero antes
de "UPDATE tickets", quedaría factura huérfana

SOLUCIÓN:
Implementar rollback en error o usar transactions
```

## 🔐 Validación de Datos - Árbol de Decisión

```
INPUT DATA
    │
    ├─► Email Validation
    │   ├─► filter_var(FILTER_VALIDATE_EMAIL)
    │   ├─► VÁLIDO → NEXT
    │   └─► INVÁLIDO → ERROR "Email no válido"
    │
    ├─► RFC Validation
    │   ├─► length 12 o 13
    │   ├─► uppercase conversion
    │   ├─► VÁLIDO → NEXT
    │   └─► INVÁLIDO → ERROR "RFC no válido"
    │
    ├─► Código Postal
    │   ├─► Integer parsing
    │   ├─► Range 1000-99999
    │   ├─► VÁLIDO → NEXT
    │   └─► INVÁLIDO → ERROR "CP debe tener 5 dígitos"
    │
    ├─► Tipo Persona
    │   ├─► in ['Fisica', 'Moral']
    │   ├─► VÁLIDO → NEXT
    │   └─► INVÁLIDO → ERROR "Tipo persona inválido"
    │
    ├─► Required Fields Check
    │   ├─► id_ticket
    │   ├─► correo
    │   ├─► rfc
    │   ├─► razon_social
    │   ├─► reg_fiscal
    │   ├─► cp
    │   ├─► tipo_persona
    │   ├─► ALL PRESENT → NEXT
    │   └─► MISSING → ERROR "Faltan datos"
    │
    └─► ALL VALIDATIONS PASS → PROCEED TO DB OPERATIONS
```
